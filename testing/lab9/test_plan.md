## 2. Тестовая среда

- Windows, Python 3.14.0, Flask 3.1.3, встроенный сервер `python app.py`.
- Адрес: `http://127.0.0.1:5077` (отдельный порт, чтобы не мешать рабочему запуску).
- БД: временная копия, создаваемая из `db/schema.sql` + `db/seed.sql`. Рабочий файл `requests.db` не используется.
- Учётные записи: шесть тестовых пользователей из `seed.sql` (admin, operator, petrov, morozov, ivanov, sokolova). Для прогона им выставляется тестовый пароль во **временной** базе. Реальные пароли в репозиторий и отчёты не попадают.
- Инструменты: скрипт `testing/lab9/run_cases.py` (HTTP-запросы к запущенному серверу, cookie-сессия для веб-форм), `curl`/Swagger UI (`/docs`) для ручных проверок API.

## 4. Виды тестов

Позитивные функциональные, негативные, граничные значения, роли и доступ, интеграционные (веб ↔ API ↔ БД), API.

## 5. Критерии

- **Начала:** приложение запускается по README, `/health` отвечает 200, БД создана из `seed.sql`.
- **Завершения:** выполнены все тест-кейсы из `test_cases.csv`, у каждого есть фактический результат и доказательство; найденные дефекты внесены в `bug_reports.md`; после исправлений проведена повторная проверка.

## 6. Порядок прогона

1. Первый прогон на коде **до исправлений**: `python testing/lab9/run_cases.py --label before` (результаты: `results_before.json`, `evidence/before/`).
2. Дефекты внесены в `bug_reports.md`, затем исправлены в коде.
3. Повторный прогон: `python testing/lab9/run_cases.py --label after` (`results_after.json`, `evidence/after/`).

## 7. Ограничения

Сценарии веб-интерфейса выполнялись HTTP-запросами с cookie-сессией (отправка форм входа, создания, смены статуса), а не кликами мышью в браузере. Визуальные проверки (внешний вид, подтверждение удаления, скриншоты) выполняются отдельно вручную, и их скриншоты прикладываются к отчёту.
