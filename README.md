# HelpDesk — Система учёта заявок

Учебный проект по дисциплине «Технологии разработки программного обеспечения».

Система регистрирует обращения пользователей, позволяет назначать исполнителей, менять статусы,
вести комментарии и историю изменений. Права зависят от роли: Администратор, Оператор, Исполнитель, Заявитель.

## Возможности

- Вход по логину и паролю, пароли хранятся только в виде хеша (PBKDF2-SHA256)
- Создание, просмотр, редактирование и удаление заявок (удаление с подтверждением)
- Назначение исполнителя, смена статуса с учётом правил ролей
- Комментарии и история изменений каждой заявки
- Поиск по номеру, теме и описанию; фильтры по статусу, категории, приоритету и исполнителю; постраничный вывод списка
- REST API с документацией Swagger и единым форматом ошибок
- Проверка работоспособности `/health`

## Структура проекта

```
app.py              точка входа: создание приложения, обработка ошибок, /health, /docs
config.py           настройки из переменных окружения
db/
  schema.sql        создание таблиц
  seed.sql          тестовые данные
src/
  web.py            контроллеры веб-интерфейса
  api.py            контроллеры REST API
  services.py       бизнес-правила и проверка прав ролей
  repositories.py   доступ к данным (только SQL)
  db.py             подключение к SQLite и инициализация базы
  auth.py           вход, сессия, HTTP Basic для API
  errors.py         ошибки приложения и их HTTP-коды
  openapi.py        описание API для Swagger
templates/          HTML-шаблоны страниц
static/style.css    стили
```

Слои: **контроллер** (`web.py`, `api.py`) → **сервис** (`services.py`) → **репозиторий** (`repositories.py`) → **база данных**.
Контроллеры не содержат SQL, сервис не формирует HTML, репозиторий не принимает бизнес-решений.

## Локальный запуск

Нужен Python 3.12 или новее.

```bash
# 1. Создать и активировать виртуальное окружение
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Linux / macOS

# 2. Установить зависимости
pip install -r requirements.txt

# 3. Запустить
python app.py
```

Открыть в браузере: <http://127.0.0.1:5000>

При первом запуске база `requests.db` создаётся автоматически из `db/schema.sql` и `db/seed.sql`.
Если у существующей базы устаревшая схема, она будет пересоздана.

Пересоздать базу вручную (все данные удалятся):

```bash
flask --app app init-db
```

### Настройки

Задаются переменными окружения (пример в `.env.example`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SECRET_KEY` | не задан (случайный ключ при каждом запуске) | ключ подписи сессий, на сервере обязательно свой постоянный. Значение-образец из репозитория (`dev-only-change-me` или из `.env.example`) приложение не принимает и не запускается (кроме `FLASK_DEBUG=1`) |
| `DATABASE_PATH` | `requests.db` рядом с `app.py` | путь к файлу базы |
| `HOST` | `127.0.0.1` | адрес, на котором слушает сервер |
| `PORT` | `5000` | порт |
| `FLASK_DEBUG` | `0` | `1` включает режим отладки (только локально) |
| `LOGIN_MAX_ATTEMPTS` | `5` | сколько неудачных попыток входа подряд допускается для пары «адрес + логин»; `0` отключает ограничение |
| `LOGIN_WINDOW_SECONDS` | `300` | на сколько секунд вход закрывается после превышения лимита (ответ 429, заголовок `Retry-After`) |

## Тестовые учётные записи

| Логин | Роль |
|---|---|
| `admin` | Администратор |
| `operator` | Оператор |
| `petrov`, `morozov` | Исполнитель |
| `ivanov`, `sokolova` | Заявитель |

Пароль тестовых учётных записей сообщается преподавателю отдельно и в репозитории не публикуется.

## Правила ролей

| Действие | Администратор | Оператор | Исполнитель | Заявитель |
|---|---|---|---|---|
| Видит заявки | все | все | назначенные ему | свои |
| Создаёт заявку | да (за заявителя) | да (за заявителя) | нет | да (от своего имени) |
| Редактирует тему, описание, категорию, приоритет | да | да, кроме закрытых | нет | свои, пока «Новая» |
| Назначает исполнителя | да | да, кроме закрытых | нет | нет |
| Меняет статус | любой переход | на шаг вперёд, кроме «Закрыта» | на шаг вперёд, кроме «Закрыта» | только «Выполнена» → «Закрыта» |
| Удаляет заявку | да | нет | нет | нет |
| Комментирует | да | да | свои заявки | свои заявки |

Статусы «В работе», «Выполнена» и «Закрыта» требуют назначенного исполнителя.

Порядок статусов: «Новая» → «В работе» → «Выполнена» → «Закрыта» (ТЗ: «последовательно»). Оператор и исполнитель переводят заявку только на шаг вперёд, пропуск и откат дают ответ 422 (`details.status_id = invalid_transition`). Администратор может любой переход, в том числе вернуть закрытую заявку в работу.

## Запуск в Docker

Нужен Docker (на Windows — Docker Desktop).

```bash
cp .env.example .env          # Windows: copy .env.example .env
# в .env задать свой SECRET_KEY; если порт 80 занят, поставить APP_PORT=8080
docker compose up -d --build
```

Открыть: <http://localhost> (или <http://localhost:8080>). Проверка: <http://localhost/health>.

| Команда | Что делает |
|---|---|
| `docker compose ps` | состояние контейнера (должно быть `healthy`) |
| `docker compose logs -f` | логи приложения |
| `docker compose down` | остановить (база сохраняется в томе `helpdesk-data`) |
| `docker compose down -v` | остановить и **удалить базу** (при следующем запуске создастся заново) |

Внутри контейнера приложение запускается production-сервером Waitress, а не отладочным сервером Flask.
Приложение работает не от root, база хранится в томе `/data` и не пропадает при пересборке.

## Деплой на сервер (Яндекс Облако, с нуля)

### 1. SSH-ключ (один раз, на своём компьютере)

```bash
ssh-keygen -t ed25519            # на все вопросы — Enter
type %USERPROFILE%\.ssh\id_ed25519.pub    # Windows (cmd); в PowerShell: cat ~/.ssh/id_ed25519.pub
```

Скопировать выведенную строку целиком (начинается с `ssh-ed25519`). Это открытый ключ, его можно показывать.
Файл `id_ed25519` без `.pub` — закрытый ключ, его никому не передавать.

### 2. Виртуальная машина

Консоль Яндекс Облака → **Compute Cloud** → **Создать ВМ**:

- образ: **Ubuntu 24.04 LTS**;
- вычислительные ресурсы: минимальные (2 vCPU с гарантированной долей 20%, 2 ГБ RAM), диск 15–20 ГБ HDD;
- сеть: **публичный IP-адрес — автоматически**;
- доступ: логин (например `student`) и вставить SSH-ключ из шага 1.

После создания скопировать **публичный IPv4** машины.
Если сайт потом не откроется, проверить в настройках сети группу безопасности: входящий TCP на порты 22 и 80 должен быть разрешён.

### 3. Подключение и установка Docker

```bash
ssh student@ПУБЛИЧНЫЙ_IP

curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
exit                              # выйти и зайти снова, чтобы группа docker применилась
ssh student@ПУБЛИЧНЫЙ_IP
docker --version                  # проверка
```

### 4. Код и настройки

```bash
git clone https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ.git app
cd app
cp .env.example .env
sed -i "s/^SECRET_KEY=.*/SECRET_KEY=$(openssl rand -hex 32)/" .env   # случайный секретный ключ
```

### 5. Запуск

```bash
docker compose up -d --build
docker compose ps                 # через ~20 секунд статус должен стать healthy
curl http://localhost/health
```

Сайт доступен по адресу `http://ПУБЛИЧНЫЙ_IP/`, документация API — `http://ПУБЛИЧНЫЙ_IP/docs`.
База с тестовыми данными создаётся автоматически при первом запуске.

### Ограничения учебного развёртывания

- Сайт работает по HTTP без шифрования: логин и пароль передаются открытым текстом. Использовать только тестовые учётные записи.
- SQLite подходит для одного сервера и небольшой нагрузки.
- Защита от подбора пароля (429 после 5 неудачных попыток) хранит счётчики в памяти процесса и сбрасывается при перезапуске. Если перед приложением поставить обратный прокси, все клиенты будут выглядеть как один адрес, и счётчик надо будет привязывать к заголовку `X-Forwarded-For`.
- После сдачи курса машину стоит **остановить или удалить**, чтобы не расходовать грант.

## REST API

Документация Swagger: <http://127.0.0.1:5000/docs> (кнопка **Authorize** → логин и пароль).

Авторизация: HTTP Basic. Все ответы в JSON, кириллица без экранирования.

| Метод | Путь | Назначение | Коды |
|---|---|---|---|
| GET | `/api/requests` | список заявок; `?search=&status_id=&category_id=&priority=&executor_id=`; постранично: `&page=1&per_page=10` | 200, 401, 422 |
| GET | `/api/requests/{id}` | заявка с комментариями и историей | 200, 401, 403, 404 |
| POST | `/api/requests` | создать заявку | 201, 401, 403, 415, 422 |
| PATCH / PUT | `/api/requests/{id}` | изменить переданные поля | 200, 400, 401, 403, 404, 415, 422 |
| DELETE | `/api/requests/{id}` | удалить заявку | 204, 401, 403, 404 |
| GET | `/api/requests/{id}/comments` | комментарии | 200, 401, 403, 404 |
| POST | `/api/requests/{id}/comments` | добавить комментарий | 201, 400, 401, 403, 404, 415, 422 |
| GET | `/api/users` | пользователи (оператор, администратор) | 200, 401, 403 |
| GET | `/api/statuses` | справочник статусов | 200, 401 |
| GET | `/api/categories` | справочник категорий | 200, 401 |
| GET | `/api/me` | текущий пользователь | 200, 401 |
| GET | `/health` | проверка работоспособности (без авторизации) | 200, 503 |

Постраничный вывод: без `page` и `per_page` приходит весь список массивом, как раньше. С ними тело остаётся массивом одной страницы (новые заявки сверху), а итоги в заголовках `X-Total-Count`, `X-Page`, `X-Per-Page`, `X-Total-Pages`. `page` от 1 до 1 000 000, `per_page` от 1 до 100 (по умолчанию 10), иное значение даёт 422. Итог учитывает фильтры и права роли. Страница списка в веб-интерфейсе показывает по 10 заявок со ссылками «Назад» и «Вперёд».

Формат ошибки:

```json
{"error": {"code": "validation_error", "message": "Поле «Тема»: минимум 3 символа, сейчас 1", "details": {"title": "min_length:3"}}}
```

Пример запроса (подставьте пароль):

```bash
curl -u operator:ПАРОЛЬ -X POST http://127.0.0.1:5000/api/requests \
     -H "Content-Type: application/json" \
     -d '{"title": "Не работает сканер", "category_id": 3, "priority": "Высокий", "applicant_id": 5}'
```
