# HelpDesk — Система учёта заявок

Учебный проект по дисциплине «Технологии разработки программного обеспечения».

Система регистрирует обращения пользователей, позволяет назначать исполнителей, менять статусы,
вести комментарии и историю изменений. Права зависят от роли: Администратор, Оператор, Исполнитель, Заявитель.

## Возможности

- Вход по логину и паролю, пароли хранятся только в виде хеша (PBKDF2-SHA256)
- Создание, просмотр, редактирование и удаление заявок (удаление с подтверждением)
- Назначение исполнителя, смена статуса с учётом правил ролей
- Комментарии и история изменений каждой заявки
- Поиск по номеру, теме и описанию; фильтры по статусу, категории, приоритету и исполнителю

## Структура проекта

```
app.py              точка входа: создание приложения, обработка ошибок
config.py           настройки из переменных окружения
db/
  schema.sql        создание таблиц
  seed.sql          тестовые данные
src/
  web.py            контроллеры веб-интерфейса
  services.py       бизнес-правила и проверка прав ролей
  repositories.py   доступ к данным (только SQL)
  db.py             подключение к SQLite и инициализация базы
  auth.py           вход, сессия, HTTP Basic для API
  errors.py         ошибки приложения и их HTTP-коды
templates/          HTML-шаблоны страниц
static/style.css    стили
```

Слои: **контроллер** (`web.py`) → **сервис** (`services.py`) → **репозиторий** (`repositories.py`) → **база данных**.
Контроллеры не содержат SQL, сервис не формирует HTML, репозиторий не принимает бизнес-решений.

## Локальный запуск

Нужен Python 3.12 или новее.

```bash
# 1. Создать и активировать виртуальное окружение
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Linux / macOS

# 2. Установить зависимости
pip install -r requirements.txt

# 3. Запустить
python app.py
```

Открыть в браузере: <http://127.0.0.1:5000>

При первом запуске база `requests.db` создаётся автоматически из `db/schema.sql` и `db/seed.sql`.
Если у существующей базы устаревшая схема, она будет пересоздана.

Пересоздать базу вручную (все данные удалятся):

```bash
flask --app app init-db
```

### Настройки

Задаются переменными окружения (пример в `.env.example`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SECRET_KEY` | `dev-only-change-me` | ключ подписи сессий, на сервере обязательно свой |
| `DATABASE_PATH` | `requests.db` рядом с `app.py` | путь к файлу базы |
| `HOST` | `127.0.0.1` | адрес, на котором слушает сервер |
| `PORT` | `5000` | порт |
| `FLASK_DEBUG` | `0` | `1` включает режим отладки (только локально) |

## Тестовые учётные записи

| Логин | Роль |
|---|---|
| `admin` | Администратор |
| `operator` | Оператор |
| `petrov`, `morozov` | Исполнитель |
| `ivanov`, `sokolova` | Заявитель |

Пароль тестовых учётных записей сообщается преподавателю отдельно и в репозитории не публикуется.

## Правила ролей

| Действие | Администратор | Оператор | Исполнитель | Заявитель |
|---|---|---|---|---|
| Видит заявки | все | все | назначенные ему | свои |
| Создаёт заявку | да (за заявителя) | да (за заявителя) | нет | да (от своего имени) |
| Редактирует тему, описание, категорию, приоритет | да | да, кроме закрытых | нет | свои, пока «Новая» |
| Назначает исполнителя | да | да, кроме закрытых | нет | нет |
| Меняет статус | любой | кроме «Закрыта» | кроме «Закрыта» | только «Выполнена» → «Закрыта» |
| Удаляет заявку | да | нет | нет | нет |
| Комментирует | да | да | свои заявки | свои заявки |

Статусы «В работе», «Выполнена» и «Закрыта» требуют назначенного исполнителя.

## Что реализовано в ЛР №6

Создание, просмотр списка и одной заявки, редактирование, смена статуса, назначение исполнителя, поиск, фильтры (статус, категория, приоритет, исполнитель), удаление с подтверждением, проверка ввода и понятные сообщения об ошибках. Бизнес-правила находятся в `src/services.py`, SQL — только в `src/repositories.py`.
