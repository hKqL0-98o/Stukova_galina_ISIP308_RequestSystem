Журнал взаимодействия с ИИ (AI Log)
Лабораторная работа №1: Анализ требований и составление ТЗ
1. Задача: Формирование ролевой модели, функциональных и нефункциональных требований для системы учёта заявок.
2. Модель: OpenAI ChatGPT-4o.
3. Промпты (сравнение вариантов):
Свободный промпт:
«Напиши ТЗ для системы учёта заявок».
Структурированный промпт:
«Действуй как системный аналитик. Составь техническое задание для учебного проекта "Система учета заявок" строго по следующим пунктам: 1. Краткое описание проблемы (2 абзаца); 2. Роли пользователя (строго 4 роли по 2 действия); 3. Функциональные требования (10 пунктов формата "Система должна...", 4 статуса, 4 категории); 4. Нефункциональные требования (5 пунктов); 5. Сущности предметной области (5 сущностей с атрибутами); 6. Критерии приёмки (4 признака). Формат: Markdown, до 350 слов».
4. Почему такой промпт: Свободный запрос не задаёт границ предметной области, что приводит к избыточности результата. Структурированный промпт фиксирует роли, количество требований, статусы и формат ответа в рамках учебного задания.
5. Почему такая модель: ChatGPT-4o эффективно работает со структурированными запросами, анализом требований и формированием документов в формате Markdown.
6. Результат ИИ:
- По свободному промпту модель выдала расширенный документ с пятью ролями, включая лишнюю роль «Руководитель», а также функциями маршрутов согласования и аналитики, не соответствующими проекту.
- По структурированному промпту был сформирован компактный каркас требований с четырьмя ролями и заданными статусами.
7. Проверка: Проведено сопоставление предложенных сущностей и требований со структурой планируемой реляционной базы данных SQLite.
8. Собственная доработка:
- Удалён атрибут «дата изменения» из статического справочника статусов.
- Уточнено правило перехода в статус «Закрыта» (закреплено исключительно за Заявителем и Администратором).
- Конкретизированы требования безопасности (указаны алгоритмы хеширования паролей bcrypt/SHA-256).
9. Вывод: Точная формулировка ограничений и ролевых рамок в промпте значительно снижает вероятность получения избыточного или неподходящего результата и помогает избежать усложнения проекта.
Лабораторная работа №4: Проектирование пользовательского интерфейса
1. Задача: Создание прототипа пользовательского интерфейса системы учёта заявок HelpDesk с помощью встроенного инструмента генерации дизайна Figma.
2. Модель: Встроенный стандартный AI-инструмент Figma для генерации макетов. Точное название базовой модели в интерфейсе не отображалось.
3. Промпты:
Промпт №1 — Создание экрана авторизации:
"Minimalist modern login screen for IT Helpdesk web app. Centered card with clean layout: app logo «HelpDesk», inputs for Email/Username and Password, «Remember me» checkbox, primary action button «Войти / Sign In», and small role switcher tabs (Admin, Operator, Technician, User) for demo preview."
Промпт №2 — Перевод надписей на русский язык:
«Переведи все текстовые надписи на созданном экране авторизации на русский язык (логин, пароль, запомнить меня, войти)».
Промпт №3 — Создание главного дашборда:
«Теперь сгенерируй справа от первого экрана второй экран: Главный дашборд со списком заявок для HelpDesk. Сохраняй ту же бело-синюю стилистику. Все надписи строго на русском языке. Вверху шапка: логотип, строка поиска, аватарка пользователя и синяя кнопка "+ создать заявку". Ниже фильтры-вкладки по статусам: "Все", "Новые", "Выполнены", "Закрыты". В центре таблица заявок по столбцам: ID, Название заявки, Категория, Приоритет, Исполнитель, Статус (цветные бейджи), Дата создания. Добавь 4-5 строк с примерами данных».
Промпт №4 — Создание формы новой заявки:
«Теперь сгенерируй справа от дашборда третий экран: Форма создания новой заявки (Create Ticket). Тот же бело-синий чистый стиль, все надписи строго на русском языке. Содержимое экрана:
Заголовок страницы: «Создание заявки в техподдержку».
Поле ввода: «Тема обращения» (placeholder: «Кратко опишите проблему»).
Выпадающий список: «Категория» (IT-оборудование, ПО, Сеть).
Выпадающий список: «Приоритет» (Низкий, Средний, Высокий).
Большое текстовое поле: «Подробное описание проблемы».
Блок загрузки файлов: пунктирная рамка с иконкой скрепки «Перетащите скриншоты или нажмите для выбора».
Кнопки внизу: серая «Отмена» и основная синяя «Отправить заявку».»
Промпт №5 — Создание экрана просмотра деталей заявки:
«Сгенерируй: Просмотр деталей заявки (Ticket Details). Единая бело-синяя стилистика, все надписи строго на русском языке. Содержимое экрана:
Шапка тикета: «Заявка #1042 — Не работает авторизация на портале», рядом бейдж текущего статуса «В работе» (желтый или синий).
Левая колонка (основная):
— Блок с полным текстом описания проблемы от пользователя.
— Прикрепленный файл-скриншот (превью картинки).
— Блок истории: «История изменений» (временная шкала: Создана -> Назначен исполнитель -> В работе).
Правая колонка (панель управления):
— Выпадающий список «Сменить статус» со значениями (В работе, Выполнена, Закрыта).
— Карточки параметров: Заявитель (Иван Иванов), Исполнитель (Петр Техник), Приоритет (Высокий), Категория (ПО).
Нижний блок:
— Лента комментариев (2-3 сообщения в виде диалога заявителя и техника).
— Поле ввода нового комментария с синей кнопкой «Отправить»».
Промпт №6 — Создание панели администратора:
«Теперь сгенерируй справа от экрана последний экран: Панель администратора (Admin Panel / User Management). Строго в той же бело-синей стилистике, все надписи на русском языке. Содержимое экрана:
Верхняя панель: заголовок «Панель администратора», подзаголовок «Управление пользователями и ролями», справа синяя кнопка «+ Добавить пользователя».
Блок быстрых счетчиков (3 карточки в ряд): «Всего пользователей: 24», «Активных: 22», «Заблокированных: 2».
Поиск и фильтры: строка поиска по ФИО/Email и выпадающий список фильтра по ролям (Все, Администратор, Оператор, Исполнитель, Заявитель).
Таблица пользователей (5 строк с примерами данных):
— Столбцы: Чекбокс, Пользователь (аватарка + ФИО), Email, Роль (бейдж соответствующего цвета: красный для Админа, синий для Оператора, зеленый для Исполнителя, серый для Заявителя), Статус аккаунта (зеленая точка «Активен»), Дата регистрации, Действия (иконки редактирования карандашом и удаления корзиной).
Внизу таблицы: простая пагинация (Страница 1 из 3, кнопки «Назад» и «Вперед»)».

Сначала был разработан экран авторизации, затем выполнен перевод текстовых элементов на русский язык. После этого добавлялись остальные экраны с подробным описанием их структуры, элементов и назначения. В каждом последующем запросе указывалось требование сохранить единую бело-синюю стилистику.

- Главный дашборд со списком заявок.
- Форма создания новой заявки.
