Техническое задание
Учебный проект «Система учета заявок»
1. Краткое описание проблемы
При отсутствии единой системы учета заявки поступают через разные каналы связи: электронную почту, телефон и мессенджеры. Информация о них хранится разрозненно, из-за чего заявки теряются, дублируются, забываются и остаются без своевременной обработки. Отсутствие контроля затрудняет отслеживание сроков и ответственности исполнителей.

Разрабатываемая программа предназначена для централизованного учета и обработки заявок. Система позволит регистрировать обращения, назначать исполнителей, отслеживать статусы, вести историю изменений и контролировать выполнение заявок.
2. Роли пользователя
1. Администратор:
- Создавать и редактировать учетные записи пользователей.
- Управлять категориями заявок.
2. Оператор:
- Регистрировать новые заявки.
- Назначать исполнителей.
3. Исполнитель:
- Просматривать назначенные заявки.
- Изменять статусы заявок.
4. Заявитель:
- Создавать заявки.
- Просматривать статус собственных заявок.
3. Функциональные требования
1. Система должна обеспечивать авторизацию пользователей по логину и паролю.
2. Система должна разграничивать права доступа в соответствии с ролями пользователей.
3. Система должна обеспечивать создание, просмотр и редактирование заявок.
4. Система должна присваивать каждой заявке уникальный идентификатор.
5. Система должна поддерживать четыре категории заявок: техническая поддержка, программное обеспечение, оборудование, прочие вопросы.
6. Система должна поддерживать четыре статуса заявки: Новая, В работе, Выполнена, Закрыта, переход в статус "Закрыта" разрешен только Заявителю (после подтверждения решения) или Администратору.
7. Система должна обеспечивать назначение исполнителя на заявку.
8. Система должна позволять добавлять комментарии к заявкам.
9. Система должна сохранять историю изменения статусов заявок.
10. Система должна обеспечивать поиск и фильтрацию заявок по номеру, категории, статусу и исполнителю.
4. Нефункциональные требования
1. Удобство: интерфейс должен быть понятным и обеспечивать доступ к основным функциям не более чем за три действия.
2. Надежность: система должна сохранять данные при штатном завершении работы.
3. Производительность: время отклика на основные операции не должно превышать 3 секунд.
4. Безопасность: Пароли пользователей должны хешироваться с использованием стойких алгоритмов, доступ должен определяться ролью пользователя.
5. Сопровождаемость: программный код должен иметь модульную структуру и документацию.
5. Сущности предметной области
1. Пользователь: ID, ФИО, логин, пароль, роль.
2. Заявка: ID, заголовок, описание, дата создания, заявитель, исполнитель.
3. Статус: ID, наименование.
4. Категория: ID, наименование, описание.
5. Комментарий: ID, текст, дата создания, автор, ID заявки.
6. Критерии приёмки
1. Пользователи могут авторизоваться, а система корректно разграничивает права доступа по четырём ролям.
2. Заявитель может создать заявку, которая сохраняется в базе данных с уникальным номером и выбранной категорией.
3. Оператор может назначить исполнителя, а исполнитель — последовательно изменять статус заявки с сохранением истории.
4. Все четыре статуса и четыре категории доступны в системе; поиск и фильтрация заявок работают корректно.
