# REST API HelpDesk: таблица endpoints

Базовый адрес: `http://127.0.0.1:5000` (локально), префикс всех методов `/api`. Формат данных: JSON (`Content-Type: application/json`), кодировка UTF-8.
Авторизация: HTTP Basic (логин и пароль пользователя). Документация Swagger UI: `/docs`, спецификация OpenAPI: `/openapi.json`.

## Методы

| Метод | Путь | Назначение | Параметры / тело | Успех | Ошибки |
|---|---|---|---|---|---|
| GET | `/api/requests` | список заявок (только те, которые доступны роли пользователя) | query: `search`, `status_id`, `category_id`, `priority`, `executor_id` | 200, JSON-массив | 401, 422 |
| GET | `/api/requests/{id}` | заявка с комментариями и историей | `id` в пути | 200 | 401, 403, 404 |
| POST | `/api/requests` | создать заявку | `title`, `category_id`, `applicant_id`; необязательно `description`, `priority` | 201 + созданный объект | 401, 403, 415, 422 |
| PATCH, PUT | `/api/requests/{id}` | изменить переданные поля | любые из `title`, `description`, `category_id`, `priority`, `status_id`, `executor_id` | 200 + объект | 400, 401, 403, 404, 415, 422 |
| DELETE | `/api/requests/{id}` | удалить заявку (только администратор) | `id` в пути | 204 без тела | 401, 403, 404 |
| GET | `/api/requests/{id}/comments` | комментарии заявки | `id` в пути | 200, JSON-массив | 401, 403, 404 |
| POST | `/api/requests/{id}/comments` | добавить комментарий | `content` | 201 | 400, 401, 403, 404, 415, 422 |
| GET | `/api/users` | список пользователей (оператор, администратор) | нет | 200, JSON-массив | 401, 403 |
| GET | `/api/statuses` | справочник статусов | нет | 200, JSON-массив | 401 |
| GET | `/api/categories` | справочник категорий | нет | 200, JSON-массив | 401 |
| GET | `/api/me` | текущий пользователь | нет | 200 | 401 |

## Правила валидации

| Поле | Правило |
|---|---|
| `title` | строка, 3–100 символов после обрезки пробелов, обязательное при создании |
| `description` | строка до 2000 символов, необязательное |
| `priority` | одно из: `Низкий`, `Средний`, `Высокий`; по умолчанию `Средний` |
| `category_id`, `applicant_id`, `executor_id`, `status_id` | положительное целое не больше 2^63−1; запись должна существовать, исполнитель и заявитель должны быть активными пользователями с нужной ролью |
| `content` (комментарий) | строка, 1–1000 символов |
| `search` | не длиннее 100 символов |
| все строки | без управляющих символов (в том числе NUL); табуляция и переводы строк разрешены |
| тело запроса | только известные поля, иначе 422 |

Статусы «В работе», «Выполнена» и «Закрыта» требуют назначенного исполнителя. Переход в «Закрыта» разрешён только заявителю (из «Выполнена») и администратору.

## Единый формат ошибок

```json
{"error": {"code": "validation_error", "message": "Поле «Тема»: минимум 3 символа, сейчас 2", "details": {"title": "min_length:3"}}}
```

| Код HTTP | Когда |
|---|---|
| 400 | тело запроса не разбирается как JSON (синтаксическая ошибка) |
| 401 | нет или неверны логин и пароль |
| 403 | роли не хватает прав на действие или на эту заявку |
| 404 | заявки или другого ресурса не существует (в том числе неподходящий по размеру id) |
| 415 | тело отправлено не как `application/json` |
| 422 | данные не прошли проверку (в том числе пустой PATCH), сообщение и поле указаны в `error.details` |
| 500 | непредвиденная ошибка или недоступна база данных (без технических подробностей в ответе) |

Примеры реальных запросов и ответов: [`examples.md`](examples.md). Команды `curl`: [`requests.sh`](requests.sh).
